## Problem addressed
Hierarchical deterministic wallets derive a key tree from a seed. A raw random seed is hard to remember or store safely; a BIP39 mnemonic is easier but security and usability conflict as entropy (and word count) grow. Shared HD wallets under those protocols are also described as hard to generate and reconstruct in a usable, secure way.

## Core mechanism
One or more biometric readings (for example a live fingerprint, optionally with liveness detection) are aligned to a reference frame and partitioned into sectors. Minutiae (count, type, direction) are encoded with a distance-preserving code such as Gray code into first binary strings, concatenated into a second representation of the whole print. Optional chained error-correcting codes (inner binary BCH, outer Reed–Solomon) absorb small reading differences and smudged sectors, yielding codewords used as the seed. That seed feeds a BIP32-style master private key and HD tree. The same reading reconstructs the seed later. Multiple readings or multiple users’ readings can be concatenated for higher entropy or a shared wallet.

## Independent claims (gist — not legal scope)
The independent method obtains biometric readings, identifies features, builds first binary representations that preserve physical differences, combines them into second representations, derives a seed, generates a master private key from the seed, and derives further private keys of a hierarchical deterministic structure from that master key.

## BSV relevance
The seed is explicitly fed to BIP32 to produce keys that sign blockchain-transaction messages or encrypt data in transaction outputs. That is a biometric enrolment path for BSV HD wallets, including shared wallets, without memorising a mnemonic.
