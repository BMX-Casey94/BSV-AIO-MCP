## Problem addressed
The specification describes a second overlay (it names Metanet) in which each node is a blockchain transaction and each edge is a parent signature plus a parent transaction identifier. Those links are static once published, so hiding or invalidating a child usually means spending a UTXO or publishing a replacement. It wants different versions of the same tree — for example depending on the day or on who is looking — without spending those outputs.

## Core mechanism
A tree creator still writes each child as a transaction that carries a data payload, its own transaction identifier, and a signature under the parent’s key. In addition each child is associated with a link identifier computed from at least one off-chain parameter (time, user or group, weights, dataset or application fields; the parent transaction identifier may also be fed in). Different children of the same parent can have different link identifiers, from the same or different functions; parameters may be encrypted; a nonce can be added so the identifier meets a proof-of-work difficulty. A tree accessor who has the parent and one or more link identifiers keeps only the children whose identifiers match, and builds a version of the tree that omits the rest. Nodes can therefore be treated as invalid for a given viewer or time without spending their UTXOs.

## Independent claims (gist — not legal scope)
Independent claim 1 is a creator method: make one or more child transactions of a parent, each with a data payload, and attach each child to the parent with a link identifier based on at least one off-chain parameter. Independent claim 13 is an accessor method that loads the parent and link identifiers, finds matching children, and builds a tree version that excludes non-matching children. Independent claims 14 and 15 are a computer system and a program for those methods.

## BSV relevance
The overlay is specified on a UTXO chain with OP_RETURN (or OP_FALSE OP_RETURN) payloads and parent signatures, and the text discusses Metanet-style graphs. Parameterised link identifiers are relevant to BSV applications that store versioned or permissioned trees on chain.
