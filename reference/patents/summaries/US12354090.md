## Problem addressed
The specification says tokenised assets on a blockchain hide the holder’s public key behind a redeem-script hash, so income paid in a different asset cannot be addressed without a separate off-chain ownership database that can drift from the ledger. Incomplete distribution transactions also cannot propagate on the chain because nodes drop unsigned transactions, and the issuer does not know how to reach the current holder. It seeks to determine current ownership from the chain alone and to embed a notification address so an off-chain message can reach an anonymous or pseudo-anonymous controller.

## Core mechanism
An oracle, triggered by an off-chain condition (for example a dividend date), walks the chain from an issuance (“anchor”) transaction to the current UTXO set for the token, then builds an incomplete distribution transaction using SIGHASH_NONE so the income output can be redirected, but only by the party who can sign the last issuance/transfer input. That incomplete transaction cannot travel on the blockchain, so a seed issuance forces every later spend to supply a notification address as metadata in the unlocking script. A redeem-script prefix counts how many notification addresses must be provided. The oracle then sends an off-chain alert (email or other identifier stored in the script) to that address, asking the holder to complete and broadcast the transaction. Each subsequent transfer can supply a new address, so the destination can change over time.

## Independent claims (gist — not legal scope)
Independent claim 1 is an electronic communication method that submits a first transaction whose unspent output has a redeem script requiring a notification address in the unlocking-script metadata, embeds that address in the unlocking script of a second transaction that spends the output, and sends an off-blockchain notification to the address. Independent claim 13 is a computer-implemented system arranged to perform that method.

## BSV relevance
The embodiment uses Bitcoin Script metadata, SIGHASH_NONE, tokenised UTXOs and an off-chain alert channel. Those are the same tools BSV applications use to reach a current token holder without a parallel ownership register.
