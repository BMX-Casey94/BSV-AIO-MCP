## Problem addressed
As transaction volume grows, storing a full public blockchain becomes prohibitively expensive, so the number of nodes that actually keep a copy falls. The specification asks how to reconfigure the network so specialised storage nodes can hold a very large chain, prove they still hold chosen parts of it, and be paid for doing so, without requiring every node to store everything.

## Core mechanism
Miners periodically sample confirmed transactions (optionally with a distribution that favours depth). After mining a new block, a miner builds a Proof-of-Blockchain-Storage (PoBS) challenge: a coinbase (or similar) output that pays a reward unlockable only by computing a hash such as H(block header ∥ selected transaction). A challenge prefix listing the selected transaction IDs is sent with a signature or in an OP_RETURN. Deeper transactions pay more, so nodes are paid more for keeping older history. A random oracle variant is described. Storage-node addresses may be certified by a group of specialised nodes using dealerless secret sharing of a group private key and bilinear pairings so two credentialed nodes can derive a shared session key without a central CA.

## Independent claims (gist — not legal scope)
Claim 1 is a miner-side method: select one or more blockchain transactions by transaction depth (blocks or confirmations after the transaction); create a proof-of-blockchain-storage transaction that identifies those transactions and a reward unlockable by a storage node that holds them; generate a challenge prefix containing their identification numbers; and send the prefix and the transaction to storage nodes. Claims 13–15 are a medium, an electronic device and a blockchain node that perform the method.

## BSV relevance
The protocol is written for Bitcoin miners, coinbase challenges, OP_RETURN prefixes and certified Bitcoin addresses. That is relevant to BSV archival/storage-node incentives as the chain grows.
