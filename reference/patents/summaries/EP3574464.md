## Problem addressed
Automated auctions usually need a trusted third party to collect bids. If that party is compromised, bidder data is exposed, and an undesirable amount of trust must be placed in it. The specification seeks a transfer method in which unsuccessful bids become automatically invalid and the party that selects the winner never receives spendable, fully signed funds.

## Core mechanism
Each buyer creates three Bitcoin transactions. T1 is a 2-of-2 P2SH output of the bid amount plus fees, redeemable only with the buyer’s signature and an oracle’s signature. T2 spends T1 back to the buyer with a locktime set to the auction end; the buyer signs it, the oracle countersigns, and it is returned to the buyer. T3 spends T1 to the seller; the buyer sends T3 unsigned to the oracle. The oracle collates bids and signs only the winning T3 (highest bid or another condition, optionally using external information). That T3 is returned to the winning buyer, who signs and broadcasts it so the seller is paid. Losing buyers broadcast their already-signed T2 refunds after locktime. Because T3 reaches the oracle unsigned, the oracle cannot take the coins; broadcasting the winner’s T3 invalidates the other spends of the same T1 output.

## Independent claims (gist — not legal scope)
Claim 1 is a method of transferring a digital asset in which each of several first users creates: a first transaction unlockable by that first user and a second user; a second transaction returning the asset to the first user; and a third transaction paying a third user. First users send the second transactions to the second user, who signs and returns them; they send unsigned third transactions to the second user, who selects one, signs it and returns it; the corresponding first user then signs and broadcasts that third transaction so the third user can redeem the asset. Claim 9 is a system for carrying out the method.

## BSV relevance
The embodiment is a Bitcoin P2SH 2-of-2 auction with locktimed refunds and an oracle that only countersigns the winning spend. That is a concrete BSV pattern for sealed or open auctions without giving the oracle custody of fully signed funds.
