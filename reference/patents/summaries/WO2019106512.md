## Problem addressed
The specification says smart-contract performance is often delegated to bots or a bot network, which needs a heavy, third-party infrastructure that itself must be secured. It wants processes to be triggered from a blockchain script under controlled conditions, without putting the full execution logic in Script and without those external bots.

## Core mechanism
A process-execution component (an interpreter, described as a plug-in or embedded add-on) sits in a digital or cryptocurrency wallet. When a transaction output is spent, the locking or redeem script can carry metadata codes, flags, instructions or parameters that the interpreter recognises as a trigger. The interpreter translates those codified instructions into executable logic and runs or starts a process. Spending still transfers a token or currency to a recipient; in addition the trigger causes a signal to an off-block destination so an off-block event can run (examples given include an email that work may start, or unlocking a device). The process may be pre-coded in the interpreter or specified in the script. A network of such wallets can read the same embedded codes as transactions propagate.

## Independent claims (gist — not legal scope)
Independent claim 1 is a system of a digital wallet plus an embedded interpreter that turns script triggers into executable logic, where spending the output transfers a token or currency and the trigger also signals an off-block destination to run an off-block event. Independent claim 9 is the corresponding method, including the interpreter’s translation step.

## BSV relevance
The specification is written for Bitcoin wallets and Script metadata on spent outputs. A wallet-side interpreter that fires off-chain actions when a BSV output is spent is a direct application of the described arrangement.
