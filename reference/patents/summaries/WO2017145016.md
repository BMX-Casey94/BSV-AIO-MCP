## Problem addressed
The specification says symmetric-key encryption needs both nodes to hold the same key, and sending that key over an unsecure network (or physically delivering it) is a serious vulnerability. It wants two nodes to determine a common secret across such a network without transmitting private keys, and to derive hierarchical deterministic keys from master pairs.

## Core mechanism
Each node registers an elliptic-curve master key pair using a shared curve and generator (the text names secp256k1 as used by Bitcoin). A shared message M is hashed to a deterministic key DK. The first node forms a second private key as V1C + DK and a second public key for the other node as P1S + DK×G, then computes the common secret as the elliptic-curve product of its second private key and the other node’s second public key. The second node computes the same secret from its second private key and the first node’s second public key. Neither private key nor the secret itself is sent. A signature on M with the derived private key lets the other node authenticate. The secret can seed a symmetric cipher; further secrets (and a tree of keys) follow from hashing previous deterministic keys or from further messages.

## Independent claims (gist — not legal scope)
Independent claim 1 is the first-node method of forming those derived keys from master keys plus DK and computing the common secret by elliptic-curve multiplication, with the matching construction at the second node. Independent claims also cover using that secret for symmetric-key communication and for an online transaction, a first-node device, a two-node system that computes the same secret, a secure-communication system built on it, and a computer program.

## BSV relevance
The description uses Bitcoin’s secp256k1 curve and names cryptocurrency wallets as an application. The same master-key plus message derivation of shared secrets and child keys is relevant to BSV wallet session keys and hierarchical key trees.
