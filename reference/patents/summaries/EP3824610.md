## Problem addressed
In a distributed network the specification wants computationally verifiable assurance that work is assigned fairly. A manager that can see workers’ choices could keep resampling until a favoured worker wins. The protocol is designed so the manager cannot tell, from the quantities workers put on the chain, whether a given worker was selected until after the task transaction is confirmed and executed.

## Core mechanism
A manager publishes trapdoor s and accumulation-tree parameters. Each worker picks a combination of leaf elements, builds a bilinear-map accumulation tree, and submits a worker ticket containing a ticket public key R_i derived from that combination and a verification public key T_i. After a time or membership cap, the manager draws its own combination, forms a third public key from it, and posts an execution transaction whose locking script involves the collected keys plus that third key, together with the computational task. Only a worker whose element set matches the manager’s can produce the corresponding private keys (a modulus relationship is used in verification) and unlock the script. Unregistered parties lack s and cannot reconstruct the tree quantities. If nobody executes in time, tickets and a protocol-rollback transaction return deposits.

## Independent claims (gist — not legal scope)
Claim 1 is a manager-node method: detect that worker transactions have formed a membership group, a first transaction carrying public keys R_i (from the worker’s chosen accumulation-tree elements) and T_i; generate a third public key from the manager’s own element set; create a second transaction that encodes a computational task and locks it with those keys; and, if the two element sets match, have that worker unlock and execute the task using the matching private keys. Claims 14 and 15 are a manager node and a storage medium that perform the method.

## BSV relevance
Worker tickets, an execution transaction and deposit/rollback outputs are described as blockchain transactions. That is relevant to BSV protocols that assign off-chain work through on-chain locks without letting the assigner pre-select the worker.
