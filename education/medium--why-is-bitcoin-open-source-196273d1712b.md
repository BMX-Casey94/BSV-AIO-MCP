# Why is Bitcoin Open Source? — core principles

- **Openness is a trust signal for money, not a security guarantee.** To an extent all software is a black box. Bitcoin is open source because it is money, and money requires trust that there is nothing hidden — openness adds trust value, not security value.
- **Software analysis cannot yield absolute assurance.** It is an NP-infeasible problem; Turing and Dijkstra showed that the state of a system can never be fully known. Open code yields a lower cost of testing and rectification, not certainty.
- **The protocol is simple; the software is what gets improved.** "It is not the protocol that needs to be tweaked, it is the software." Extension belongs in Script — a predicate that can be seen to always end.
- **Bitcoin's core achievement is competitive double-spend prevention.** A competitive system whose global nature blocks the regulatory capture that lets incumbents in ordinary capitalist systems suppress competition.
- **Saltzer and Schroeder's 1975 protection maxims are the design fundamentals.** Economy of mechanism, fail-safe defaults, complete mediation, open design, separation of privilege, least privilege, least common mechanism, and psychological acceptability. The last is commonly overlooked: unusable security gets bypassed.
- **Absolute security does not exist.** The goal is that the economic constraints placed upon the attacker exceed the perceived benefits. Attackers are rational economic actors who maximise gain and minimise risk.
- **Security is comparative, not absolute.** The question is not "am I secure?" but "am I more secure than my neighbour?"
- **DoS is not a design criterion.** Hit any system with a sustained attack from a billion bots and it goes down. What matters is evidence creation and minimising long-term risk.
- **Lock the original protocol and build on it.** Locking the original protocol as closely as possible, then building, is what allows Bitcoin to be cash and to scale.
