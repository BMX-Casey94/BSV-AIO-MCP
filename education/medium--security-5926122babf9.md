# Security — core principles

- **Security is an economic function.** All software development is an economic function: quality varies with cost — if you want more assurance, you pay more, exactly as with locks, alarms and cars.
- **Assurance is priced and quantifiable.** Rigorous manual security review runs at around 190–220 lines of C per hour on a good day (less for assembly); verifying a system the size of Windows at that level would take over 50,000 man-hours before any fixes — verified software is affordable, but nobody wants to pay.
- **Baseline security should be assumed, not optional.** Input validation, boundary conditions, encrypting data as necessary, least privilege, and white lists over black lists are baseline engineering, yet the industry treats them as chargeable extras.
- **Every change expands the attack surface.** Each addition, update or modification multiplies the room for error; for a money system, each change and each experiment is an uncompensated security risk imposed on every user.
- **SegWit as the exemplar of change-as-risk.** Altering the transaction structure (moving signatures out of the transaction ID) is cited as the flagship experiment that enlarged the attack surface while changing what the system is — a technical contrast that shows why base-layer change must be minimised.
- **Lock the protocol and let usage pay miners.** The remedy is a stable protocol on which business can use Bitcoin for any purpose it is willing to pay miners for — stability, not functionality, is the security feature.
- **Bitcoin is cash, not a social programme.** You get what you pay for; the system's purpose is sound money, not social equality.
