# Open Source
**Date:** 2020-01-24 | **URL:** https://medium.com/@craig_10243/open-source-ed8e1066fbbd
**Subtitle:** The real need for open source software has been hijacked by a political agenda. I did not create bitcoin is open source software because I…

## Core thesis
Craig argues that Bitcoin was released as open source for a narrow security reason — Kerckhoffs' principle that only the key, never the algorithm, should be secret — and not from any free-software or anti-copyright ideology. The open-source movement, he claims, has been "hijacked by a political agenda" that conflates analysable code with free code in "a truly Orwellian" attack on property rights. Bitcoin is an open protocol for commercial construction, "anything but anti-capitalist", and "works with law". The Medium post is an excerpt; the body continues on craigwright.net.

## Key arguments and claims
- "I did not create Bitcoin as open-source software because I believed that software should be free. Rather, as one of the most highly qualified security professionals at the time, I understood the basic rules of cryptography lay in open algorithms."
- Kerckhoffs' law (1883): "a well-designed cryptographic system should be constructed so that only the key needs to be secret. There should be no secrecy in the algorithm"; the proprietary alternative — security by obscurity — "in general terms... is snake oil".
- "There is a major difference between software that is free and software that is open source": open source means the ability "to analyse source code and ensure the integrity of the system"; activists have subverted this into "an attack on copyright and property rights in general".
- Releasing freeware remains an author's right, but security software specifically must be analysable so "vulnerabilities [are] found quickly".
- From his antivirus/malware-reversing career: "Source code itself cannot be fully hidden. So in not releasing code, you slow down yet do not deter the analysis of the system vulnerabilities. In so doing, you asymmetrically incentivise the attacker."
- Proprietary secrecy produces fragility: "It requires more secrets to be kept"; conversely, "The fewer secrets a system has, the more secure it can be."
- Kerckhoffs' principle "does not specify open-source software because it came about before the implementation of software at all" — it requires public algorithms and peer review, because "nearly every cryptographic system that has ever been created is insecure and has a vulnerability".
- "Bitcoin is not designed to deliver free software, it is designed to be an open protocol that any organisation can build upon and create commercial applications on top of... Bitcoin is anything but anti-capitalist. It works with law, and it doesn't enable the anti-government, anarchist view of a collapsed society."

## How Craig reasons (his model/logic)
Historical-first-principles reasoning: he reaches back to Kerckhoffs (1883) to separate the security function of openness from its later political packaging, then deploys an attacker/defender incentive asymmetry (secrecy burdens the honest analyst more than the attacker) drawn from his own reverse-engineering career. The rhetorical mode is boundary-policing — defining what open source properly means and expelling the free-software ideology as Orwellian mission creep — in service of a property-rights, pro-commercial reading of Bitcoin's design.

## Where this contradicts BTC-mainstream logic
- Contradicts the free-software/cypherpunk reading of Bitcoin's licence: openness was a cryptographic-engineering decision, not a political donation of code to the commons; copyright and property rights remain fully intact.
- Contradicts the anti-commercial, anti-capitalist strain of crypto culture: Bitcoin exists so "commercial organisations can build" on an open protocol.
- Contradicts security-by-obscurity practices in proprietary/altcoin projects: closed source "asymmetrically incentivise[s] the attacker" and yields fragile systems.
- Implicitly contradicts the "code is law / code is speech" conflation: the system's legitimacy comes from analysability plus law, not from escaping law.
