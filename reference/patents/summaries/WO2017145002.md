## Problem addressed
The specification says data on a personal device (laptop, tablet, phone) is often protected by a short PIN that can be guessed, or by a password whose strength depends on what the user can memorise. A cryptographic key stored on a USB drive still has to be transmitted to the device, and electromagnetic leakage during that transfer can expose the key. The problem it states is how to protect stored data without transmitting the secret key itself to the electronic device.

## Core mechanism
An electronic device and a separate key device each hold an elliptic-curve master key pair (the embodiment names secp256k1). The electronic device hashes a message to a deterministic key DK, derives a second device private key V2S = V1S + DK and a second key-device public key P2C = P1C + DK × G, and computes a common secret from V2S and P2C. That secret becomes a symmetric encryption key for files or the disk — the embodiment derives it as a hash over the message (as salt), the secret and the device serial number; only the message (or DK) is sent to the key device. Decryption reconnects the key device, optionally authenticates it with an ECDSA signature on an authentication message using a similarly derived key pair, retrieves the stored message, and recomputes the same secret. Private keys are never exchanged.

## Independent claims (gist — not legal scope)
Independent claim 1 is a method of encrypting data on an electronic device associated with a key device: determine DK, receive the key-device public key, derive a second device private key and a second key-device public key from the masters and DK, form a secret from those second keys, encrypt with the secret or a key based on it, and send information indicative of DK to the key device. Independent claims 23 and 25 claim a matching computer system and electronic device that store or send that DK information on the key device; a further independent claim covers a computer program embodying the method.

## BSV relevance
The embodiment uses secp256k1, SHA-256 and ECDSA — the same primitives Bitcoin (and therefore BSV) wallets use for keys and signatures. The specification is about encrypting data on a personal device rather than about blockchain transactions.
