# When Every Block Counts, Except the Ones That Don't
**Date:** 2026-08-01T04:15:37.695Z | **URL:** https://singulargrit.substack.com/p/when-every-block-counts-except-the
**Subtitle:** What the mathematics of bounded-anticone certification says about the blockDAG protocols — and why the problem is in the specification, not the code

## Core thesis
BlockDAG protocols — PHANTOM, GHOSTDAG and the parameterless DAGKnight — promise to abolish the orphan waste of Nakamoto consensus by keeping every block and certifying the honest ones. The essay shows that the device by which they decide which blocks "count" — a local density condition, bounded-anticone (k-cluster) certification — cannot deliver that promise, and that this is a property of the specification, not of any implementation. The waste is not abolished but relocated: from a visible orphan rate to an invisible demotion rate.

## Key arguments and claims
- The mechanism: an ordering rule reads the local graph of blocks (who named whom at creation) and from that graph alone produces a total order plus a certified subset. Certification governs reward and the weight a block lends to its descendants; uncertified blocks keep their slot in the order but are demoted.
- The graph-theoretic core: the anticone of a block is the set of blocks that neither reach it nor are reached from it — concurrently created blocks whose relative order the graph does not settle. A set is a k-cluster if every member has at most k other members of the set in its anticone. The rule is: certify a k-cluster. The intended intuition is that an honest block's anticone is confined to about two network delays, while a withheld block's anticone swells with the concealment — a test for concurrency-that-was-honest versus concurrency-that-was-manufactured.
- First crack — the test cannot be exact. An all-honest run (two blocks created within one delay) and a run in which a single faulty node withholds an identical block for exactly one delay produce the same labelled graph. Since the rule reads the graph alone — no trustworthy clock, no authenticated creation time, no verified author; timestamps are strings a faulty author writes at will — it must answer identically in both runs. Either it certifies withheld blocks generally, or it demotes honest blocks in a run where nobody misbehaved. "Faulty" is a fact about history and the graph does not carry history; the question is never whether honest blocks get demoted, only how many.
- The veto, and its exact price. If k + 1 certified blocks sit in the anticone of a block z, then z cannot be certified — by definition, certifying z would violate the k-cluster condition. The price is exactly k + 1, tight on both sides: with only k certified blocks in the anticone the target remains certifiable (a k-cluster containing it exists), and a pairwise-incomparable certified set can have at most k + 1 members. So k + 1 is at once the smallest force that vetoes and the largest incomparable set that certifies — the attacker operates precisely at the ceiling the honest protocol sets for itself. No timing, block-rate or probabilistic assumption is needed, and the result holds even for rules that certify a largest possible k-cluster. Raising k widens the anticone the honest set tolerates, weakening the very detection the condition exists to perform.
- The fan: one node, no waiting. A single faulty node creates k + 1 blocks that all name a common ancestor and name none of one another; nothing obliges a faulty node to reference tips it holds, so the blocks are pairwise concurrent by construction and can be minted in a single instant and released together. Fan plus trunk is itself a valid k-cluster — each fan block has exactly k others in its anticone, within bound — so the extreme violation of the honest naming discipline passes the density test at its maximum admissible width. One fan vetoes every block on every chain forking from its anchor: pointed at r chains of length N it demotes rN honest blocks at a fixed cost of k + 1, a damage-to-cost ratio that grows without bound. In the machine-checked instances, a fan at k = 124 — a parameter in the range deployed systems have used — demotes just under twenty-four honest blocks per attacker block. That is a count, with no rate assumption.
- The two-optima result. A graph can carry two maximum k-clusters of identical cardinality 1 + L + N: P (the k + 1 witnesses padded with a ballast chain) and Q (the honest target chain itself). A rule certifying P attains the exact optimum — zero cardinality error — while leaving every one of the N honest blocks of Q uncertified, each belonging to the equally optimal Q. The loss lives in membership, not size, so approximation-ratio analysis is the wrong instrument; N is free, so honest loss is unbounded even at ratio exactly one. The smallest instance fits in nine blocks, checked by hand and by machine; the honest chain can be built by a scrupulously honest node in an admissible run.
- It gets worse without an adversary. Under an ordinary transient network partition, if both sides produce more than k blocks, then in any certified k-cluster at least one side must have at least (its size − k) blocks left out — deterministically, growing with the partition's length, with no faulty node anywhere. The mechanism forces honest blocks to cancel each other under exactly the conditions a partition-tolerant system is meant to weather.
- Two further properties: certification is not monotone — a fan arriving into a block's anticone can push the count past k and un-certify a block that looked settled. And demotion is not merely a label: under natural rules placing uncertified blocks after the certified blocks they are concurrent with, the fan shoves every honest block behind the k + 1 blocks one faulty node minted in an instant — the device meant to stop manufactured concurrency jumping the queue lets it jump the queue.
- Why it is not fixable: every result is proved for the entire class of rules defined by three conditions — the certified set is a k-cluster, the order respects reachability, and the rule reads the graph alone — cardinality-optimal members included. Removing the defects requires changing what "certified" means (abandoning the k-cluster condition, or adding a forbidden input such as a trustworthy clock, authenticated identity or an assumed concurrency bound) — each a different protocol with different assumptions.
- Stated limits: no claim that any deployed network has suffered these failures (admissibility is not empirics); nothing about agreement — honest nodes may converge, and if they do, they agree on the demotion; silence on which side of a split loses. The single probabilistic claim — the time to accumulate k + 1 blocks follows a Gamma law under a Poisson model of block creation — is explicitly flagged; everything else is combinatorics true in every admissible run. Constructions are machine-checked by exhaustive subset enumeration, with maximum-k-cluster optimality proved rather than estimated on the smaller instances. References: Sompolinsky & Zohar (2018); Sompolinsky, Wyborski & Zohar (2021); Sompolinsky & Sutton (2022).

## How Craig reasons (his model/logic)
Pure counting arguments about graphs, with probability deliberately quarantined. He defines the rule class minimally (k-cluster certification, reachability-respecting order, graph-only input) and then proves class-wide results: indistinguishability (identical labelled graphs force identical outputs), exact tightness of the veto price by definition-chasing, unbounded membership loss via two optima of identical cardinality, and deterministic exclusion under partitions. The machinery is an information-availability argument — the graph does not carry history, so no statistic can recover it — combined with adversarial construction (the fan) and symmetry between right answers. Because the defects follow from the defining conditions rather than from any approximation to them, no better member of the class exists to retreat to.

## Where this contradicts BTC-mainstream logic
The immediate target is the blockDAG family — alternatives to Nakamoto consensus with real deployment and real money — but the argument also inverts a criticism of Bitcoin that much of the mainstream accepts: that Nakamoto's orphaning of honest work is pure waste to be engineered away.
- Against the "every block counts" promise: every block counts only "in the trivial sense that every block stays in the order"; which blocks count "in the sense that matters — reward, weight, precedence" is decided by a mechanism whose deepest properties "run against the promise".
- Nakamoto's waste is at least "visible and quantifiable" as the orphan rate; blockDAGs relocate it to an invisible demotion rate "that no measure of certified-set size detects, that a single faulty node can drive up at fixed cost without waiting, and that a blameless network partition can produce with no faulty node at all".
- Against implementation optimism ("real implementations are cleverer"): the results hold for cardinality-optimal rules, so "there is no better member of the class to escape to".
- Against probabilistic reassurance, where "most of the marketing lives": the troubling results "need no probability at all".
- He explicitly declines to bury blockDAGs — the analysis is "not a reason to abandon the idea of ordering a graph instead of a chain" — but demands the ordering device be costed exactly rather than described as delivering what its name suggests.

## Notable quotes
- "There is no predicate computable from the graph that fires on exactly the faulty blocks, because 'faulty' is a fact about history and the graph does not carry history."
- "The number k + 1 is at once the smallest force that vetoes and the largest incomparable set that certifies. The attacker operates precisely at the ceiling the honest protocol sets for itself."
- "The waste has not been abolished but relocated — from a visible orphan rate to an invisible demotion rate."
- "The honest blocks are no longer deleted. They are kept, and reordered behind the attacker's, and not paid, and the accounting shows a full ledger the whole time."

## Connections
The essay names no other essay in the set and shares no references with them. Its baseline is Nakamoto consensus — whose orphan rate it treats as honest, visible waste against the blockDAG alternative — the same Nakamoto design whose fee-funded security "The Defence That Halves" quantifies and whose open admission "There Is No Such Thing as Spam in a Priced System" defends. Argumentatively, however, it stands alone: a graph-theoretic examination of PHANTOM, GHOSTDAG and DAGKnight.
