## Problem addressed
A party may need to attest that a signature belongs with a previously registered value without exposing the signing private key. The specification also describes linking two on-chain identities through a shared secret so a third party can check the relationship from public keys alone.

## Core mechanism
A recorded blockchain transaction holds a registered value that is a one-way function of a first secret value. To attest, the signer forms a signature as a one-way function of that first value and a message (for example an HMAC), publishes a first transaction carrying the signed message, then publishes a second transaction that reveals the first value. Verifiers check that applying the one-way function to the revealed value recovers the registered value. The first value itself may be a one-way function of a further secret, so later revelations extend a hash chain. The description also has Alice derive a second private key from her first private key plus a shared secret with Bob, so a third party can test whether P2 equals P1 plus the shared-secret public point.

## Independent claims (gist — not legal scope)
A method attests a signature by recording a registered value that is a one-way function of a first value, generating the signature as a one-way function of that first value and a message, publishing a signed-message transaction, then publishing a second transaction that reveals the first value so others can recompute the registered value. Equipment and program claims cover performing that method.

## BSV relevance
On-chain commit-then-reveal attestation of a hash-based signature, and optional public-key linking via a shared secret, can support BSV identity and KYC-style address relationships without putting the private key on chain.
