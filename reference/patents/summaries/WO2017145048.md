## Problem addressed
Large organisations run hierarchical, non-blockchain systems (illustrated as general ledgers with many sub-ledgers) that must ingest data posted on a public chain without adapting either protocol. The specification says existing financial systems require synchronising many databases, and that extracting, attributing and posting blockchain activity to the correct internal structure is difficult while preserving integrity and interoperability.

## Core mechanism
Each element of an organisational structure is given a public/private key pair. A root key sits at the top; child keys are derived deterministically with elliptic-curve techniques: a deterministic key is the hash of a message chosen to mean something (for example an account or invoice number), and a sub-key is the parent public key plus that deterministic key times the generator G. A collector scans the blockchain for transactions whose keys match the derived set, extracts amounts, metadata and timestamps, and matches them to accounts using the known derivation rule. The resulting records are written to posting files (optionally hashed, encrypted with a calculated secret, and signed with the structure private key) and posted to an internal ledger, a DHT, or back onto the chain as metadata. The same derivation family is also used to compute shared secrets between nodes.

## Independent claims (gist — not legal scope)
Claim 1 is a method that identifies a first-structure public-key set (root plus sub-keys), derives the deterministic association between them, extracts from blockchain transactions both a first-structure public key and data about a transfer involving that structure, and generates an output by matching extracted data to the key set. The sub-keys are generated with ECC from a deterministic key that is a hash of a message arranged to convey a meaning or link to the entity. Claim 16 is a computer system arranged to implement the method.

## BSV relevance
The specification is about scanning Bitcoin-style transactions by deterministically derived keys and posting the result into an organisation’s books. That is relevant to BSV wallet, explorer and enterprise-reconciliation tooling that attributes on-chain activity to internal accounts.
