## Problem addressed
Distributed systems (the specification uses cooperating compute nodes and, as an example, modules of a driverless car) need an enforced order of processing steps, a tamper-resistant record of the path taken, and cryptographic control of resources and hierarchy, without a central voting authority and without assuming that choices are independent.

## Core mechanism
Non-supervisory nodes sit in a cycle with a supervisor. Each possible outcome of a node’s step has an ECC key pair. Working backwards from the supervisor, each node receives public values that combine the supervisor key with every combination of later outcomes, adds its own outcome keys to form state values, and shares those values. Payment channels are then built around the cycle: each T_pay can be unlocked by any of the unlocking values that correspond to the next node’s received values (sums of the private keys along a path plus the supervisor private key). Execution starts at the far side of the cycle: a node waits for the next node’s T_pay to appear, reads the revealed unlocking value (which encodes earlier outcomes), chooses its own outcome, adds its matching private key, and unlocks the previous channel. Refund transactions abort if time runs out. The locked resource is recovered only by using the accumulated secret, so a node cannot skip the prescribed order.

## Independent claims (gist — not legal scope)
Claim 1 is a distributed-control method in which a node in a cycle (the nodes corresponding to modules of a system) receives values for combinations of later processing outcomes, builds state values from those values plus its own outcome public keys, shares the state values, and prepares a blockchain transaction that transfers a resource to the next node when any unlocking value matching the received values is supplied. Claims 13 and 14 are a system and a storage medium for the method.

## BSV relevance
The protocol is built on Bitcoin payment channels, nLockTime refunds and ECC-summed unlocking values to force an order of off-chain decisions onto the ledger. That is relevant to BSV payment-channel circuits and multi-party control flows.
