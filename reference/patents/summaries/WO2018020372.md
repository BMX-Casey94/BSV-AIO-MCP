## Problem addressed
Two parties may need to exchange assets on a blockchain when no prior relationship or trust exists. Without a binding inter-dependency, one party could claim the other’s asset without completing the swap, or both could be left without a timed refund path.

## Core mechanism
Alice posts a payment transaction whose output can be unlocked either by Bob’s signature plus a secret X that only she initially knows (hashed in the locking script), or by a 2-of-2 of Alice and Bob. Bob posts a ticket (token) transaction with the same dual path: Alice’s signature plus X (and a redeem script holding ticket metadata), or the same 2-of-2. When Alice spends the ticket with X, X appears on-chain and Bob can claim the payment. Staggered locktimed return transactions (ticket return earlier than payment return) let each party reclaim their asset if the other does not complete. A fifth refund transaction can be held by a third party if the underlying event is cancelled.

## Independent claims (gist — not legal scope)
One independent method has the first user generate a first output locked by a hash of secret data X and redeemable with unlocking data that includes X, exchanged for a second output locked the same way, so that spending the second output reveals X for the second user to claim the first. The other independent method is the counterpart from the second user’s side: generate the second output under the same hash-lock so that the first user’s redemption of it reveals X for claiming the first output.

## BSV relevance
The embodiment is a Bitcoin Script atomic swap using OP_IF hash-locks, 2-of-2 refunds, nLockTime, and P2SH token metadata — directly applicable to trust-minimised exchange of satoshis and tokens on BSV.
