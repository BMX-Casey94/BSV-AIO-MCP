## Problem addressed
The specification says traditional IoT networks depend on a single master that issues commands, which is a single point of failure: if that master is disrupted, the hierarchy cannot be monitored or controlled. It seeks a layered overlay, bridged to a blockchain, in which several master nodes each control a subset of intermediate nodes and end devices, and one master can take over another’s subset when control is impaired.

## Core mechanism
IoT (layered-network) nodes sit in an ordered stack: a core of master nodes, each connected to blockchain nodes; one or more intermediate layers; and a device layer of end devices. Under normal operation each master commands its own intermediate subset (and those nodes command their end devices) by issuing command transactions — typically a signature of the master and an output locked to the target node’s public key, with command data (device identifiers) in an unspendable output. Masters detect problems with a peer master by failed connections, missing command transactions, stale device status, load or privacy alerts, or explicit indications from other nodes. The first master then issues command transactions to the affected intermediate nodes of the second master’s subset, optionally completing a partial request transaction. Digital certificates issued down the layers can be revoked to drop connections. The overlay may follow Mandala-like community rules on ancestor and intra-layer links.

## Independent claims (gist — not legal scope)
Independent claim 1 is a method, performed by a first master node of such a layered network, of identifying one or more issues that affect the second master’s control of at least one of its intermediate nodes and, in response, issuing a command transaction to that intermediate node. Independent claims 14 and 15 cover computer equipment and a computer program that perform the method.

## BSV relevance
Command and request transactions are described as Bitcoin-style P2PKH outputs with off-chain or on-chain command data, used to control IoT devices. That is a BSV-shaped pattern for hierarchical device control with on-chain audit.
