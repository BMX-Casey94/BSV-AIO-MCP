# Security in a world of IPv6 and Bitcoin — core principles

- **End-to-end security replaces the perimeter.** The "crunchy shell" firewall model gives way to IPv6 networks in which every host is individually firewalled and all sessions are encrypted — a well-defined cloud-plus-IPv6 deployment can be more secure than the traditional perimeter model.
- **Policy-controlled client isolation.** Group Policy restricts clients to encrypted sessions with trusted servers only, because client peer-to-peer communication is a malware-dissemination vector with rarely any legitimate need.
- **Data-centre desktops neutralise physical attacks.** Desktop-as-a-Service with keyed tablets means users are never actually on the system; a lost device yields at most a key to a remote desktop that still requires authentication, with no data loss if configured correctly.
- **Bitcoin integrates payment at the network layer.** IPv6 flags allow payment to be embedded in network sessions; with IPv6 jumbo blocks and Bitcoin as the payment channel, the result is a path to an Internet of Value on demand.
- **Machine-to-machine micropayments are the endgame.** Ubiquitous addressing (RFID/IP-tagged goods, disposable communication tablets, web-addressable devices) plus a cash system capable of tiny transactions makes per-service network payments practical — payments integrated at the network layer, not a settlement-only chain.
- **Mobility follows from architecture.** With every session encrypted and restricted to the device and organisational servers, user location is irrelevant while the organisation keeps control through its proxy and mail servers.
- **Controlled infrastructure is a security strength.** Proxies, host firewalls and centralised policy deliver accountability — controlled, auditable infrastructure beats decentralisation for its own sake.
