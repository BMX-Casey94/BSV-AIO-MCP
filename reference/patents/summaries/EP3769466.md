## Problem addressed
Zero-knowledge contingent payments need a proof that encrypted data is correct and that the decryption password is the value that will be revealed on-chain to claim payment. zkSNARKs used for such composite statements are computationally heavy, have large proving keys, rely on strong pairing assumptions, and need a trusted common reference string. Proving statements that mix a hash pre-image with an elliptic-curve private key is described as especially costly in that framework.

## Core mechanism
The prover represents the statement as an arithmetic circuit and commits to wire values with Pedersen commitments (individually or batched). Sigma protocols for addition and multiplication gates, plus a key-opening of a chosen wire, let the verifier check circuit satisfiability and compute an elliptic-curve public key P = s·G for the same secret s that is the circuit input (for example a SHA-256 pre-image). For a contingent sale the prover locks offered data as pk_V + i·G, proves that i is both the circuit input and the discrete log of pk_P, and the verifier pays with a transaction spendable by the prover’s signature plus i; revealing i on-chain lets the verifier derive the full decryption key.

## Independent claims (gist — not legal scope)
The independent method has the prover send a circuit statement (function output h equals the discrete log of point P), wire commitments, h, and a proving key so the verifier can check the circuit and the key-statement. The same claim then uses that proof in a zero-knowledge contingent transaction: the verifier’s payment is unlocked by revealing locking value i, which is both the circuit input and the addend that completes the data’s private key.

## BSV relevance
The contingent-payment embodiment spends a Bitcoin-style output by revealing a hash pre-image that is also an elliptic-curve scalar. That is the same script pattern BSV applications use for hash-locked fair exchange, without requiring pairing-friendly SNARK curves.
