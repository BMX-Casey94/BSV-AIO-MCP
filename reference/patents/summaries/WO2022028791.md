## Problem addressed
Lightweight clients that lose their connection to a blockchain node cannot submit transactions or check UTXOs. The specification wants those users to reach the network through an ordinary internet service that already has a persistent connection to several nodes.

## Core mechanism
An internet server (web or mail) keeps connections to multiple blockchain nodes and acts as a gateway. A first-party user sends part or all of a transaction through that hosted service — for example a webpage form, SMTP, or an embedded signer. The server forwards the transaction to the nodes. It also maintains a contact list of parties associated with the user together with those parties’ blockchain addresses, and returns the list so the user can pay the correct address. Status updates can include the transaction itself, an indication that it has been published in a block, and a Merkle path for that inclusion.

## Independent claims (gist — not legal scope)
A first-party method sends at least part of a blockchain transaction via an internet service that is connected to blockchain nodes and receives a contact list of associated parties that includes their blockchain addresses. A server method receives that transaction part, forwards it to the nodes, and maintains and returns the contact list. Equipment and program claims cover those methods.

## BSV relevance
A web or mail gateway that submits BSV transactions and returns pay-to addresses from a hosted contact book is a practical access path for users who cannot keep a node connection.
