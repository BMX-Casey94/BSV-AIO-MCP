## Problem addressed
Proof-of-work miners secure a permissionless chain, but there is no built-in way to register and later revoke a miner’s public identity without a certificate authority. The specification says relying on a CA conflicts with the aim of transfers that do not depend on a trusted intermediary, and that being able to verify a miner (or pool) matters for protocol-change consensus and related uses. Bitcoin SV is named as an illustrative protocol.

## Core mechanism
The miner first broadcasts a validity-check transaction (VCT) with an arbitrary spendable input, a first output paid to an address the miner controls, and a second OP_RETURN output carrying the miner identifier (a public key PK_ID). After the VCT confirms, the miner includes in a generation (coinbase) transaction an OP_RETURN field with the same identifier, a reference (TxID) to the VCT, and optionally an action code and a signature under sk_ID. Another node verifies identity by loading the generation transaction and the referenced VCT, checking the identifiers match, and testing that the VCT’s first output is still in the UTXO set. Spending that output revokes the identifier immediately, without waiting to mine another block. Updating publishes a new VCT and a new generation transaction that links old and new identifiers with both signatures.

## Independent claims (gist — not legal scope)
Claim 1 is a method of registering and verifying a mining node: the miner creates and propagates a validity-check transaction with a miner-controlled output and an information field holding a miner identifier, then mines a generation transaction whose information field repeats the identifier and references the validity-check transaction; a second node retrieves both transactions, checks the identifiers match, and treats the identifier as valid only while the first output remains in the UTXO set. Claims 12 and 13 are a computing device and a computer-readable medium that perform the method.

## BSV relevance
The specification illustrates the method on Bitcoin SV generation transactions, OP_RETURN identity fields and UTXO-set revocation. That is directly applicable to BSV miner identity, pool authentication and any process that should treat coinbase-declared keys as revocable credentials.
