## Problem addressed
Anyone may mine on a permissionless chain, and protocol changes need miner agreement, yet there is no on-chain way to register a miner’s identity or prove a work history without trusting a certificate authority. The specification wants identity, revocation and a reputation score backed by proof-of-work.

## Core mechanism
A miner first publishes a validity-check transaction (VCT) with its identifier public key PK_ID in an OP_RETURN output and a spendable output it controls; spending that output revokes the identity. It then mines a registration generation (coinbase) transaction that repeats PK_ID and references the VCT. Later blocks it mines contain generation transactions that again carry PK_ID and a pointer (txid, block number or outpoint) to the previous generation transaction in the chain, plus a pointer back to the registration transaction and a signature. Another node walks that chain backwards, checks the earliest registration and that the VCT output is still unspent, and optionally computes a reputation score as a count of those blocks or a sum of per-block weights 2^256 / T_i from each block’s difficulty target. A vote can be cast by mining a further generation transaction that includes a vote signal and the score.

## Independent claims (gist — not legal scope)
A method traces a chain of generation transactions that share a miner identifier and, except the first, point to an earlier generation transaction in a block mined by the same node, then verifies registration of that identifier in the earliest transaction, treating the chain as the miner’s work history. Device and medium claims cover performing that method.

## BSV relevance
Coinbase-linked miner identity and difficulty-weighted reputation are usable on BSV for miner authentication, protocol-vote weighting and CA-free public-key registration of mining pools.
