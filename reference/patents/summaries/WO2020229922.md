## Problem addressed
Bitcoin-style SHA-256 mining can be parallelised across ASICs, which the specification links to higher energy use, hardware inequality, and possible centralisation of hash power. Proposed ASIC-resistant hash changes are described as having limited success. The disclosure wants consensus and chain security without a parallelisable puzzle.

## Core mechanism
Miners agree a common, timestamp-ordered set S of exactly N transactions (plus a reward transaction) so they attempt identical candidate blocks. A block is valid only with a cryptographic link to the previous header, a representation R of the transactions (for example a Merkle root), and a proof-of-computation C from a non-parallelisable function F. F takes transaction-identifier hashes, the previous-header hash, and an adjustable difficulty t; the worked example is recursive modular exponentiation / repeated squaring, so each step needs the previous output. Dummy hash-chain identifiers pad the set when fewer than N transactions are available. The first miner to finish C publishes a proof-of-computation message; others verify by computing the same sequential function.

## Independent claims (gist — not legal scope)
The independent method mines a block that contains a set S of exactly N transactions, with N and the order agreed so that the network attempts identical blocks, and an output that is a proof-of-computation from a non-parallelisable algorithm whose inputs include an adjustable difficulty parameter and a hash of at least one transaction and/or block header.

## BSV relevance
The specification describes an alternative consensus puzzle for a Bitcoin-like ledger, not a change to BSV’s existing SHA-256 proof-of-work. Relevance is limited to research on sequential mining designs; it does not describe a mechanism that BSV nodes implement today.
