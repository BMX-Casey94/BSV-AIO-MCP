# Managing Blockchain Automata — core principles

- **External Autonomous Agents.** A bot is External (code is not embedded in Bitcoin Script), Autonomous ("the host machine on which the bot runs does not control the bot but only provides computer resources") and an Agent (it executes logic for a client, not its host) — a remunerated, non-malicious botnet working in parallel to the Bitcoin network.
- **Three market roles.** Client (pays for functions), Service Provider (creates and distributes bots, maintains KYC databases, vets clients and hosts on "reputation; credit rating"), and Host (commits CPU and storage).
- **Metered micropayment fees.** Fee structures meter by CPU usage, storage, number of executions, execution time, "success criterion", or event triggers; payment mechanisms include ordinary bitcoin transactions, tokenised bitcoin transactions and payment channels.
- **Payment channels for ongoing engagements.** A worked scenario pays through a 12-month payment channel with a locktime "payback" transaction — channels handle recurring metered settlement without per-event on-chain cost.
- **Bot identity is a Bitcoin address.** Each bot's unique identifier is an address derived from an ECDSA master key pair it generates; secret sharing and key splitting can shard private-key knowledge across service provider, host, client, "regulatory authority; escrow service; trustee".
- **Function secrecy with certification.** Protocols let hosts execute bots whose code is never revealed to them, with bot categorisation and certification as the safety guarantee against liability or harm.
- **Messages as transactions.** The communications module includes a code for "send message as bitcoin transaction" with parameters INPUT-TX-ID and amount — the chain doubles as the control and audit channel.
- **Configuration taxonomy.** Parallel networks (SETI@home-style), competing networks (brute-force tasks where the winner claims "the 'prize' by unlocking a bitcoin transaction with the solution"), cooperative swarms (fire-spotting drones), bot hierarchies with manager bots, and standalone agents (an arbitrage bot on a laptop).
- **Codification doctrine.** Every bot function is reduced to tables and parameterised functions so it can be manually coded, generated by a "Bot Compiler", or run by an interpreter on a trusted server.
