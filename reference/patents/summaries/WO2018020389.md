## Problem addressed
The specification describes known unidirectional micropayment channels (funding transaction plus a series of replaceable payment transactions, only the last of which is mined) and says the asset transferred on chain is decoupled from the customer–merchant agreement. In a dispute the merchant cannot readily show the correlation, or impose contract conditions on supply, other than by redeeming the latest replaceable transaction and closing the channel.

## Core mechanism
A merchant mints machine-executable smart contracts as coloured-coin tokens: a minting transaction pays to a 1-of-3 CHECKMULTISIG script whose “public keys” are metadata pointing at the off-chain contract (for example in a DHT) plus the merchant’s public key. The customer selects a contract/token, builds a funding transaction that spends the token into a 2-of-2 output (customer and merchant signatures) with a customer-only refund after locktime, signs it and sends it to the merchant. Each required payment produces a replaceable transaction that spends the funding output, pays an incremented amount to the merchant (2-of-2), returns the token, and is signed by the customer and held by the merchant. Only the final replaceable transaction is submitted. The token may carry machine-executable control data (for example to cut access on unauthorised use).

## Independent claims (gist — not legal scope)
Independent claim 1 is a method, at a first user’s computer, of implementing a micropayment channel: select a contract and a token from a published minting transaction; generate, sign and send a funding transaction that spends the token into a 2-of-2 output; and, on each payment request, generate, sign and send a replaceable transaction that spends that output, pays an updated amount to the second user under 2-of-2, and returns the token, the token comprising machine-executable code.

## BSV relevance
The embodiment uses Bitcoin-style coloured-coin tokens, P2SH/multisig scripts, locktime refunds and replaceable off-chain updates — the same micropayment-channel and token patterns used on BSV.
