## Problem addressed
A UTXO chain can carry a second data chain. The specification gives cases where a secondary blockchain or its network becomes unviable (for example through lack of hash power) and units on that chain should be preserved, where a private chain needs integrity proofs on a public core chain, or where any append-only log (messages, move-ordered games) should inherit the core chain’s immutability and traceability.

## Core mechanism
Users build ML transactions made of carrier pairs: an input and an output at the same index, the output holding secondary-chain data (raw or hashed, often after OP_RETURN) and the input holding a signature that signs only that pair (SIGHASH_SINGLE|ANYONECANPAY is described so pairs can be lifted into a larger transaction without breaking signatures). An ML block producer gathers pairs — they may even come from transactions that are invalid on the core protocol — into one core transaction, keeping matching input/output indices, and adds a chain output spent by the next ML block’s chain input, forming a UTXO-linked ML chain. The chain output may carry a Merkle root of the embedded data and may be locked with a proof-of-work puzzle, a producer key, a multisig or threshold key, a hash puzzle or an r-puzzle. In the secondary-blockchain example, a producer embeds secondary transactions and a secondary coinbase, peers on the secondary network verify the candidate ML block, then the producer signs a fee input and broadcasts the ML block onto the core chain.

## Independent claims (gist — not legal scope)
Claim 1 is a method, performed by an ML block producer, of embedding a data chain on a core blockchain: obtain ML transactions each containing signed input–output carrier pairs whose outputs hold data-chain data; generate a first ML block that is itself a core transaction containing those pairs (input index matching output index) plus a first chain output to be spent by a later ML block; and cause that ML block to be recorded on the core blockchain. Claims 14 and 15 are computer equipment and a program that perform the method.

## BSV relevance
The core chain is a UTXO/Bitcoin-style ledger; carrier pairs use Bitcoin sighash types and OP_RETURN embeddings. That is relevant to BSV as a settlement or integrity layer for other chains or append-only application logs.
