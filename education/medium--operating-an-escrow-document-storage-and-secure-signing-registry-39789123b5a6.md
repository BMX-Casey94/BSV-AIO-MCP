# Operating an Escrow Document Storage and Secure Signing Registry — core principles

- **Sole key control is incomplete for real assets.** Document and value systems must be engineered for court-recognised recovery — probate, insolvency, audit — rather than treating key loss as irrecoverable.
- **Escrowed keys enable lawful third-party access.** Data can be encrypted so that escrowed keys let an estate executor or a corporate liquidator reach the contents without the owner's signing and encryption key.
- **Integrity is a timestamp plus a signature.** Store documents in a time-stamped, digitally signed format so that the record cannot be altered and integrity can be proved.
- **Authenticity can be checked without disclosure.** External parties can validate that a document is authentic without having to read its contents.
- **Custodial storage is a designed role.** A server can receive user data to be securely stored and maintained, with encryption and escrow as first-class properties rather than afterthoughts.
- **Legal institutions are legitimate accessors.** Executors and liquidators are named recovery paths by design — inheritance and insolvency are protocol-adjacent requirements, not attacks on the system.
