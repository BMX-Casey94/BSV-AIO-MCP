## Problem addressed
Time-release encryption is meant to encrypt a message now so that it cannot be decrypted until a chosen future time. Pure time-lock puzzles are imprecise and computationally expensive for the decryptor; a trusted agent who promises to reveal a key on time is accurate but requires trust. The specification wants a public-blockchain service that incentivises timely, correct key release without the client ever holding the private key.

## Core mechanism
An agent generates an encryption key pair and a short successive-squaring time-lock puzzle on the private key. Zero-knowledge proofs show that the hash pre-image is the private key matching the published public key, and that the puzzle output relates to that key. A Bitcoin transaction takes the client’s fee and the agent’s deposit. Outputs pay the agent only after time t if the private key is revealed; anyone who obtains the key plus the puzzle value before t can take the deposit; after t + Δt the client can reclaim fee and deposit. Revealing the key on-chain unlocks the outputs. A multi-agent variant uses dealer-free m-of-n secret sharing so each agent posts a share under its own contract.

## Independent claims (gist — not legal scope)
The independent method constructs a digital time-lock contract specifying an agent deposit, a client fee, an encryption public key, and a window [t, t+Δt] for releasing the matching private key. The contract allows the fee and deposit to move to the client (or anyone, for the deposit) if the key and a derived time-lock-puzzle value appear early; to the agent after t if the key is released with the agent’s signature; and to the client after t+Δt if nothing was released.

## BSV relevance
The contract is expressed in Bitcoin Script with hash-locks, CHECKLOCKTIMEVERIFY, and OP_RETURN public-key metadata. The same output-spending rules could be used on BSV to pay an agent for publishing a decryption key only inside a defined time window.
