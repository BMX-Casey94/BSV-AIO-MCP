# Set in Stone
**Date:** 2018-11-15 | **URL:** https://medium.com/@craig_10243/set-in-stone-7ebc9d31500e
**Subtitle:** Bitcoin was always designed to be sound money

## Core thesis
Bitcoin's core design was fixed at version 0.1 and any alteration of the protocol is a wealth transfer — "less than a zero-sum game" — that subsidises one party at the expense of the majority, which is precisely the defect of fiat money Bitcoin was built to stop. Craig concludes that Bitcoin SV will restore the original 0.1 protocol and then "scale to the world."

## Key arguments and claims
- "Stable money" means a fixed supply, not stable purchasing power: Bitcoin "has a set amount, not that you can buy a set quantity of anything with it."
- "If you alter money, you always change the 'rules of the game.' You cannot change Bitcoin without subsidising one party and taking from another. Any change is less than a zero-sum game" — protocol changes are economically destructive redistribution, and this "is the key problem with fiat as we have it now."
- He quotes Satoshi's bitcointalk post: "once version 0.1 was released, the core design was set in stone for the rest of its lifetime," with script generalising transaction types "so transacting parties can describe their transaction as a predicate that the node network evaluates."
- Bitcoin's purpose "was always to create sound money. It is not anonymous, and it is not designed to facilitate anarchy and destroy the state" — a P2P electronic cash "that cannot be debased."
- He quotes Satoshi against alternative implementations: "I don't believe a second, compatible implementation of Bitcoin will ever be a good idea… a second implementation would be a menace to the network" — because all nodes must get "exactly identical results in lockstep."
- Governance is hash power, not votes: "The system is controlled by CPU (hash) power, and it is not a democracy"; Satoshi: "the majority version wins if there's any disagreement, and that can be pretty ugly for the minority version."
- "Bitcoin SV will return Bitcoin to what it was supposed to be, from the start and at 0.1. Then, we scale to the world."

## How Craig reasons (his model/logic)
The method is originalist exegesis: he quotes Satoshi's own bitcointalk statements as authoritative text and derives present-day policy (lock the protocol, reject alternative implementations, hash-power arbitration) directly from them. Layered on top is a welfare-economics argument — any rule change is negative-sum redistribution — which converts protocol conservatism from preference into economic necessity. The rhetorical mode is declarative and valedictory, published on the day of the BCH/BSV split.

## Where this contradicts BTC-mainstream logic
- Rejects the BTC development model itself: continuous soft-fork upgrades (SegWit, and later Taproot-style changes) are framed as fiat-style debasement — "any change is less than a zero-sum game."
- Contradicts the "Bitcoin is an anti-state, anonymous, censorship tool" narrative: "It is not anonymous, and it is not designed to facilitate anarchy and destroy the state."
- Attacks multi-client diversity (a mainstream robustness virtue, e.g. BTC Core vs alternatives, and ETH's multi-client ethos) using Satoshi's "menace to the network" line.
- Denies governance-by-community/rough consensus: "it is not a democracy" — hash power alone arbitrates, and minority chains deserve their "ugly" fate, a direct hash-war-era justification.
