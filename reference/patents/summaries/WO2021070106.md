## Problem addressed
Full nodes combine mining, validation, storage and propagation, but those roles have incompatible hardware needs. Separating them must not introduce a trusted intermediary. Low-bandwidth mining sites also suffer if they must receive and send entire blocks. The specification wants an atomic exchange so a non-mining node can assemble a candidate block and a mining node can be paid only if a valid proof-of-work is revealed.

## Core mechanism
In one embodiment the non-mining node builds a candidate block containing a source transaction (output to itself) and a miner transaction that spends that output to the miner. It sends the miner the Merkle root (or header), the miner transaction, and a Merkle path — not the source transaction — so the miner can prove inclusion without seeing the full block, then hashes nonces until a proof-of-work is found and returns the nonce. In another embodiment many miners receive the same header; a successful miner sends H(header); the non-mining node double-hashes it against the difficulty and only then creates a miner transaction locked by revelation of the pre-image header. The non-mining node completes and propagates the block.

## Independent claims (gist — not legal scope)
One independent method (non-mining node) generates a candidate block with a source transaction and a miner transaction, sends Merkle root, miner transaction and Merkle path, receives a proof-of-work, and propagates the block. A counterpart independent method has the mining node validate inclusion from the Merkle path, mine the header, and return the nonce. Two further independent methods cover the post-hoc variant: the miner sends a hash of the proof-of-work and receives a miner transaction locked by the solution before revealing it.

## BSV relevance
The embodiment uses Bitcoin-style candidate headers, double-SHA256 proof-of-work, coinbase/generation outputs, and Merkle proofs. It is a way to split BSV pool-manager and hash-rig roles while keeping payment atomic with the solved block.
