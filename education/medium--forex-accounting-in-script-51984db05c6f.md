# Forex accounting in script — core principles

- **Script can host Ricardian contracts.** Restored BSV Script can carry agreements that are simultaneously human- and machine-readable and legally enforceable — the blockchain "killer application" for business process, not a substitute for law.
- **Law is law; code is evidence.** "Law is law, and code is mere evidence at best." Enforceable electronic contracts must satisfy paper-and-ink-equivalence requirements that have been debated since 1980s EDI admissibility problems.
- **Tax can settle at transaction time.** An online store can charge VAT on local sales, sell VAT-free internationally with customs fees incorporated, and use tokenised notes to "instantly pay any and all tax that it has collected" — simplifying small-business contracting and letting governments collect revenue with minimal interference.
- **Forex and atomic swaps record themselves.** Linked to a common exchange, a smart contract can complete an atomic swap and record the foreign-exchange evaluations, storing all gains and losses for automatic regulatory reports — including Bank Secrecy Act filings "without even the click of a button".
- **Bitcoin as base protocol or FX rail.** The same construct can incorporate consumer credit and hire purchase, and can use Bitcoin as the base protocol or as the exchange rail between national currencies.
- **Pseudonymity can still bind identity.** A deterministic key system allows pseudonymous publication that is linked immutably to identities, so a contract signature remains legally binding.
- **Implementation, not mere ideas.** "A mere idea does not matter, an implementation does." Five contract scenarios — public asset registry; asset registry with hidden ownership; lease; rolling contract; contract conditionality — cover equities, property titles and rolling forward-payment contracts.
