## Problem addressed
The specification says day-to-day exchanges of value — financial and non-financial — are slow and costly on conventional rails, and that known blockchain exchanges still rely on third-party escrows and multi-currency processors. It seeks a way for parties to offer, request and exchange entities (cryptocurrency, tokens representing contracts, goods or services) on a peer-to-peer distributed ledger while keeping a permanent record of offer, acceptance and exchange, without altering the underlying blockchain protocol.

## Core mechanism
An invitation is encoded as metadata (entities to exchange and conditions) placed in a redeem script together with the inviter’s public key and a third-party public key (escrow or token issuer). The script is hashed and that hash is locked in a pay-to-script-hash invitation transaction on the ledger; the full script and hash may also be published on a distributed hash table so the hash acts as a look-up key. Matching invitations are paired by overlapping conditions. Exchange is completed by one or two exchange transactions that spend the invitation outputs, presenting the redeem scripts signed by the users and third parties, and paying the counterparties. Tokens are issuer-signed contracts pegged (or not) to the underlying cryptocurrency amount; metadata occupies script slots designated for public keys so nodes that do not interpret the metadata can still relay the script.

## Independent claims (gist — not legal scope)
Independent claim 1 is a method that receives a first invitation, builds a redeem script containing the invitation metadata, the first user’s public key and a third-party public key (with the metadata embedded in a public-key slot), hashes that script, and sends both the script/hash and an invitation transaction locking a digital asset to that hash onto a peer-to-peer ledger. Independent claims 22 and 23 cover a processor or group of processors, and a computer-readable medium, configured to perform that method.

## BSV relevance
The embodiment is written against Bitcoin P2SH, Script public-key slots used as metadata carriers, DHT-backed invitation records, and issuer-signed tokens. That maps directly onto BSV script, token and off-chain pointer patterns for peer-to-peer exchange.
