## Problem addressed
The specification describes conventional Bitcoin-style proof-of-work as miners repeatedly hashing until they find a nonce below a difficulty target, with no requirement to execute a predetermined sequence of steps. It wants a proof-of-work protocol that is inherently sequential (non-parallelisable) so that simply adding more parallel hash hardware is not enough, while still operating on a Bitcoin-like network.

## Core mechanism
A committee of three or more independent trusted nodes generates, for each new block cycle, a set of collision-resistant multiparty computational challenges and allocates a different challenge to each miner, optionally at random. Each challenge requires calculation of an RSA modulus that is then used in a repeated-squaring time-lock puzzle. Solving it uses an inherently sequential algorithm: recursion, modular exponentiation and/or repeated squaring, so each step’s output is the next step’s input. Generation of a challenge may use a random or pseudo-random input and/or an RSA key pair. A miner may add its own data so its solution is unique. A new set of challenges is distributed at the start of each cycle (each new block).

## Independent claims (gist — not legal scope)
Independent claim 1 is a method that generates a plurality of multiparty computational challenges and provides each mining node on a proof-of-work blockchain network with a respective challenge, characterised in that the challenge comprises calculation of an RSA modulus used in a repeated-squaring time-lock puzzle.

## BSV relevance
The specification describes a Bitcoin-protocol proof-of-work that replaces repeated SHA-256 nonce search with sequential RSA time-lock puzzles issued per miner. That is a consensus-layer construction for a Bitcoin-derived network such as BSV.
