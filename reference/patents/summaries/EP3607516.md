## Problem addressed
The specification says blockchain addresses are only pseudo-anonymous: external analytics can link transactions to people. CoinJoin-style mixing still leaves at least one participant who knows another’s input–output pairing. It wants untraceable, unlinkable distribution of data records (cryptocurrency, documents, exam scripts, crime reports, survey returns) from many input addresses to many output addresses.

## Core mechanism
Input nodes each hold a share of a group private key e (unknown to any one of them) and obtain a group public key Q of the output nodes. Via secret-share joining (Lagrange interpolation of elliptic-curve terms) they reconstruct a group public key P for the inputs and a shared secret s from Q and their shares. They build a first transaction that spends the many input UTXOs to a stealth address A_pool = Q + s·G, embedding P after OP_RETURN. Output nodes, holding shares of the private key d behind Q, scan for that OP_RETURN, recompute s from P and their shares, confirm A_pool, then collaboratively ECDSA-sign a second transaction that pays the pooled records out to the designated output addresses, using threshold “secure inverse” and “secure multiplication” so d + s is never assembled at a single node.

## Independent claims (gist — not legal scope)
Independent claim 1 is an input-node method: obtain the output-group public key Q, obtain a share of an unknown input-group private key, collaboratively derive the input-group public key and a shared secret, and generate a transaction that collects the input records to a stealth address based on Q and that secret. Independent claim 6 is the matching output-node method: find that transaction, recompute and check the stealth address, and collaboratively sign the distribution transaction with ECDSA using the shared secret and the output key share.

## BSV relevance
The embodiment is specified against Bitcoin scripts (OP_RETURN, ECDSA, UTXOs) and threshold key shares. The same stealth-address pooling and collaborative signing pattern could be used for unlinkable payouts or document submission on BSV.
