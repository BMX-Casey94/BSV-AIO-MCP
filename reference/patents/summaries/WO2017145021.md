## Problem addressed
The specification says payroll and similar multi-entity records must be stored, processed and transmitted securely, with an immutable history of changes. It seeks to use a public peer-to-peer ledger as the repository of accounts for payroll (or like) information, and to transfer cryptocurrency between many nodes without exposing master private keys, while carrying payroll metadata on the transfer.

## Core mechanism
On a transfer request, a generator value is formed from a string associated with the first node that identifies the second user or the purpose of the derived key (tax withheld, superannuation, mortgage, college fund, pay period, and so on). From each party’s master public key and that generator value, a second public key is derived (P2 = P1 + GV·G in the ECC description). An output script is built from transfer metadata (payslip-like fields, or a hash or pointer to them) placed in P2SH multisig public-key slots together with the second node’s second public key, and a data output locking the cryptocurrency quantity to that script is sent to the ledger. The same generator value can yield a common secret for encrypting metadata in transit. Keys may be spawned in a chain or tree so different payroll purposes have distinct addresses. Tokens representing employment rights and benefits may ride with the cryptocurrency quantity.

## Independent claims (gist — not legal scope)
Independent claim 1 is a method that, on a request to transfer cryptocurrency from a first node to a second node, derives a generator value from a first-node string identifying the second user or key purpose, derives second public keys for both nodes from their master keys and that value, builds an output script from transfer metadata and the second node’s second public key, and sends a ledger data output locking the cryptocurrency to that script. Independent claim 13 is a system with a processing device configured to perform those steps.

## BSV relevance
The embodiment uses Bitcoin P2SH metadata, deterministic ECC child keys, and the public ledger as a payroll account book. Those are the same script and key-derivation tools used on BSV for labelled payments and on-chain records.
