# The Failure of BTC Core’s Changes — core principles

- **Bitcoin was designed as practical digital cash.** Fast, cheap transactions down to micropayments, an extensible scripting system for escrow and conditional payments, and a scaling model in which throughput grows with hardware, bandwidth and storage.
- **Script's contract capability is a design feature, not a risk to be stripped.** Opcode removal framed as "safety" cripples escrow and conditional payments; withholding technical capability is exclusionary conduct, not prudence.
- **The 1 MB block limit was a temporary anti-spam safeguard, not a sacred parameter.** It was expected to scale with technology; fixing it manufactures artificial scarcity in block space and a contrived fee market — deliberate output restriction.
- **Transaction malleability is a manageable characteristic.** It is addressed by not relying on transaction IDs before confirmation; elevating it into an existential flaw is a pretext for restructuring, not a necessary fix.
- **Soft-fork "compatibility" can be coercive.** A new block-weight accounting that preserves a nominal cap is accounting sleight of hand, not genuine scaling; making one rule-set the default without explicit agreement is unilateral imposition disguised as continuity.
- **Base-layer throughput is the scaling path.** A separate system of pre-funded channels introduces counterparty risk, liquidity constraints and usability barriers — a substitute that creates dependence, not a solution to an unscalable ledger.
- **Miners are the intended economic decision-makers.** Passive nodes serve no critical function in consensus; social signalling that "everyone can verify" by running a personal archive conflates observation with authority.
- **Ossification at a restricted state is paralysis, not stability.** Freezing the protocol before it has scaled is abdication; restriction is not safety, and empirical evaluation of throughput must replace ideological slogans.
