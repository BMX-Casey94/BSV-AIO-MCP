## Problem addressed
Distributed systems (the example is aircraft subsystems and their subcomponents) need an enforced processing order and a tamper-resistant audit trail. Earlier cyclically-ordered payment-channel protocols could order steps among nodes of one ring, but not among subcomponents of a subsystem, and could not skip a subsystem.

## Core mechanism
Nodes sit in cyclically-ordered sets; each set has an initiator, and the initiators themselves form a second cycle (a two-dimensional structure). A first initiator generates a private key, distributes publicly verifiable secret shares to the other nodes of its set, and derives a locking value from the public keys of those shares. It prepares a payment-channel transaction that moves a resource to the next node only when a corresponding unlocking value is supplied, and starts a circuit of like channels around the set. A parallel circuit among initiators uses locking values built from the other initiators’ public keys. Revealing an unlocking value (optionally combined with a late-revealed initiator secret) lets the next node proceed; withholding it skips that subsystem. Payment channels use commitment, refund and payment transactions with decreasing nLockTime. Nodes recover committed resources only by using an accumulated secret derived from prior step outputs.

## Independent claims (gist — not legal scope)
A method has a first initiator generate a private key and shares, compute a first locking value from the shares’ public keys, prepare a transaction that pays the next node in its cycle when a matching unlocking value is supplied, and start a circuit of such transactions around the set. System and medium claims cover that method.

## BSV relevance
Nested payment-channel circuits that enforce step order with hash/secret unlocks are a BSV pattern for multi-stage workflows (including optional skip) with an on-chain audit of who proceeded.
