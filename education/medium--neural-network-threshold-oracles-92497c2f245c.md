# Neural Network Threshold Oracles — core principles

- **A node can act as a perceptron.** "The vote or firing sequence is based on the use of a threshold and address" — Bitcoin-funded nodes fire signed transactions in response to external inputs, and the mechanism extends to particle-swarm-optimised and genetic-algorithm code "when the node is also funded using Bitcoin".
- **Threshold signatures are the signalling rail.** Inputs use a threshold-signature system and "send signed transactions to the next layer based on external input or other events", triggered either "on block" or via "CPFP (Child Pays for Parent) chained transactions" — Script and fee-bumping carry the oracle's messages.
- **Layered risk architecture.** An input layer with one neuron per system or application maps "IP options, malware, and buffer overflow conditions, selected attacks"; a hidden layer combines current, prior and external data; the output layer yields "an economic risk function" — insurance pricing, risk modelling and security monitoring become automatable.
- **The blockchain is the audit layer.** It "allows for auditing of the system and the ability to validate the inputs and ensure the integrity of the system", and the same perceptron mesh can serve as a "control point for IoT devices and any other agent-based system".
- **External threat feeds lose data.** Existing services ship "clipped data": attacks take time to diagnose, so "much otherwise useful data is lost" outside baseline alerting thresholds — on-chain, economically funded oracles retain the full signal.
- **Honest limitation.** Training requires "the determination of the correct weights for each neuron" — feasible for selected systems, "a far larger effort" for generalised deployment.
