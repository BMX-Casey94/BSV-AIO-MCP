## Problem addressed
Information stored in blockchain UTXOs is heavily hashed and formatted, so recovering a meaningful message — in particular the current state of a machine-executable contract implemented as a deterministic finite automaton — is not practical by inspecting the raw chain. Existing search methods do not extract that state efficiently.

## Core mechanism
A state (or tag) of the contract is hashed into metadata, placed in an “information public key”, and combined with the public key of the agent assigned to spend the UTXO for that state, typically as a 1-of-2 P2SH multi-signature redeem script. The scriptPubKey (hash of the locking script) becomes a key in an external mapping (for example a Python dictionary or DHT). Script-hash addresses derived from those values are loaded into a wallet. A search-and-match pass finds UTXOs whose script-hash addresses match the wallet addresses and maps those UTXOs back to the keys, thereby identifying which state is present. The same reproducible construction that created the on-chain bytes is used to build the search terms.

## Independent claims (gist — not legal scope)
A method generates an information public key from metadata for a given contract state, combines it with an agent public key, builds an external mapping of the resulting search term, finds matching UTXOs, extracts information from them and determines the contract state. A system claim covers implementing that method, optionally with a computing agent that runs a DFA on a blockchain.

## BSV relevance
Finding DFA or smart-contract state by matching P2SH script hashes in the UTXO set is directly applicable to BSV contracts that already encode state in P2SH locking scripts.
