# Set in Stone — core principles

- **The core design was fixed at v0.1.** Satoshi: "once version 0.1 was released, the core design was set in stone for the rest of its lifetime"; script generalises transaction types so transacting parties can describe their transaction as a predicate that the node network evaluates.
- **Stable money means fixed supply, not fixed purchasing power.** Bitcoin was designed as stable money in the sense that it has a set amount — not that you can buy a set quantity of anything with it.
- **Any protocol change is negative-sum redistribution.** If you alter money, you change the rules of the game; you cannot change Bitcoin without subsidising one party and taking from another — any change is less than a zero-sum game, which is the key problem with fiat money as we have it now.
- **Sound money was the design intent.** The purpose of Bitcoin was always to create sound money — P2P electronic cash that cannot be debased; it is not anonymous, and it is not designed to facilitate anarchy and destroy the state.
- **Alternative implementations threaten consensus.** Satoshi warned that a second, compatible implementation of Bitcoin would be a menace to the network, because all nodes must get exactly identical results in lockstep.
- **Governance is hash power, not democracy.** The system is controlled by CPU (hash) power; the majority version wins if there is any disagreement, and that can be pretty ugly for the minority version.
